Quickstart#

Install AmberClaw, configure your environment, verify subsystems with doctor, and launch.

Step 1: One-line install (sh)

terminal · sh
curl -fsSL https://amberclaw.pages.dev/install.sh | sh

Step 2: Environment Configuration

Edit .env to configure your LLM providers and secrets (see .env.example ↗):

.env
# Core Configuration
AMBERCLAW_ENV=development
AMBERCLAW_WORKSPACE_DIR=./data/workspace
AMBERCLAW_SECRET_KEY=your-32-byte-secret-key

# LLM Providers (Configure at least one)
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
OLLAMA_API_BASE=http://localhost:11434

# Security Controls
AMBERCLAW_AUTH_ENABLED=true
AMBERCLAW_RATE_LIMIT=10

Step 3: Run System Diagnostics (doctor)

AmberClaw includes an automated doctor command that verifies configuration paths, provider keys, sandbox dependencies, and permissions:

terminal · bash
uv run amberclaw doctor

Output highlights verified subsystems:

  • ✓ Config file valid
  • ✓ Workspace directory writable
  • ✓ Provider keys detected
  • ✓ Execution backend dependencies ready

Step 4: Launch AmberClaw

Option A: Interactive CLI Mode

terminal · bash
uv run amberclaw agent

Option B: FastAPI Gateway & Web Dashboard

terminal · bash
uv run uvicorn amberclaw.api.main:app --host 0.0.0.0 --port 8000 --reload

Navigate to http://localhost:8000 to access the Web Dashboard SPA.

Option C: Guided Onboarding Wizard

terminal · bash
uv run amberclaw onboard

Architecture#

An asynchronous message bus decouples ingress interfaces from planning, state, sandboxes, and governance.

Messaging channels · FastAPI gateway · CLI
↓
Asynchronous message bus
↓
Agent planning · LiteLLM · SessionDB
↓
Approval · isolation · audit · tool execution
  • Interfaces: Chat channels, CLI, and HTTP endpoints.
  • Planning & Routing: Model selection and tool calls.
  • State: Searchable session history and agent profiles.
  • Execution: Backend selection via the terminal factory.
  • Governance: Audit logging and human approval tickets.

Security#

Layered controls: Linux Landlock confinement, credential redaction, authenticated APIs, approval tickets, and SHA-256 hash-chained audit logs.

FILESYSTEM

Landlock LSM

Confines subprocess filesystem access on supported Linux kernels.

TRACEABILITY

Hash-chained logs

Append-only JSONL audit events for tamper detection.

API

Authentication

Bearer JWT, API keys, rate limits, and CORS controls.

GOVERNANCE

Approval queue

Routes sensitive operations to human review before execution.
